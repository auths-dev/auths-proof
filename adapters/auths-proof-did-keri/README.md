# `auths-proof-did-keri`

This crate proves control of a narrowly supported `did:keri` principal from a
bounded, self-contained KERI event log (KEL). It is a principal adapter, not an
authority engine: Auths decides whether an action was authorized; this crate
only decides whether the signer controlled the principal named by a statement.

## Supported profile

- KERI 1.0 JSON `icp`, `rot`, and `ixn` events
- Blake3-256 (`E`) self-addressing identifiers and next-key commitments
- simple numeric signing and next-key thresholds
- Ed25519 and P-256 controller keys
- indexed and dual-indexed CESR controller signatures
- zero-witness, fully embedded KEL evidence

Delegated inception/rotation, weighted thresholds, witnesses, receipts, live
OOBI resolution, and claims of current controller state are deliberately not
supported. Unsupported input fails closed.

## Independent oracle

`tests/fixtures/keripy/` contains byte-for-byte fixtures generated by keripy
1.3.4: a threshold-2 inception with three keys followed by a threshold-2
rotation to two keys using dual-index signatures. They were selectively copied
from the pre-greenfield `auths-keri` tests; no production implementation was
copied.

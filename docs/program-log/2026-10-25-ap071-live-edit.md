# AP-SPEC-071 Jules Project A live edit, 25 October 2026

This run exercised the first Google read and exact-confirmation edit milestone of
[AP-SPEC-071](../specs/0071-human-agent-read-write-delegation-demo.md). It is
not the spec's full acceptance run.

Jules signed one 30-minute task for a distinct registered agent. The task
permitted one Project A source read release of at most 16 KiB and one edit to
the separate run-owned working Doc. The agent signed its read and write
actions with its own key. Its private release channel acknowledged 51 bytes
from the source Doc. Durable gateway status recorded one provider read, one
release, 51 released bytes and `agent-acknowledged`.

The agent-signed proposal replaced one marker in the working Doc with a
144-byte update derived from the released source probe. Jules separately
signed the exact Google Docs batchUpdate body and target revision. The gateway
recorded one write and a complete HTTP 200 response. It did not claim a
provider effect from that response alone.

demo_co then ran its independent, read-only `google write-inspect` using its
admin-side observation path. Its private generation-0002 observation file has
SHA-256 `5c88d6e0181be05650e8d7e56db477ff77e74cb629108cfb943b4c609889a12f`.
The observed target was the pinned working Doc. Its text changed from the
generation-0001 baseline of 65 bytes, SHA-256
`09dbb59b25f9023002f9539616c559bb31da981c3f43d5ffd2da3aeebae40a05`,
to 179 bytes, SHA-256
`e24c0601353eb3244b629df4ba7e606fe68dea1df35329ee62879482e3d9ccbd`.
The independent readback found a contiguous 144-byte span at offset 35 with
the exact approved replacement SHA-256
`14f2fdaa92fa6445f662981a13fe5a98dab5ece1ad79b98fc7453ab0f60649e4`.
Replacing that span with the original marker reconstructs the pinned baseline
hash. The replacement contains the old marker token as part of a longer source
probe ID, so a raw substring count remains one; there is no standalone marker
line. This is observed provider state consistent with the one authorized
replacement, while the Auths proofs and journal establish who authorized and
entered that request. Neither the HTTP response nor the independent readback
alone proves exclusive causation.

The live run exposed two gateway proof-admission defects, fixed on this branch:
the read path used the installed write audience instead of the reviewed read
recipe's audience, and it rejected the tool-scoped human child grant even
though the activated task supplies the exact resource, account, expiry and
budget limits. Regression tests cover a mixed read/write context and task
admission. Post-claim credential renewal, create/populate, bounded-upfront
writes and the cross-provider acceptance case remain open.

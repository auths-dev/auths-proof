# AP-SPEC-079 Packaged developer and operator rehearsal

Use the maintained Stripe platform refund demo to measure whether a developer
and an operator can complete distinct workflows from the packaged artifacts
and public instructions. Use the native gateway and installed SDK with the
existing counting provider double. Run in disposable Linux containers with
network disabled during execution. All credentials are synthetic. Record the
archive and constituent package digests, exact Auths source revision, field-lab
baseline, workflow run, environment, and the documentation each participant saw.

| Existing owner | Reuse and evidence boundary |
| --- | --- |
| Stripe and Airtable gateway demos | Installed native execution, approval, bounded budgets where applicable, process races, and response loss. Stripe is the measured workflow. Airtable is complementary evidence about linked read-back and competing writers. |
| Cross-company and Google demos | Related coverage for authority, sensitive disclosure, or SDK deployment paths. Their results do not establish Stripe recovery or packaged developer onboarding. |
| Qualification simulator and operator package | Existing disposable ceremony, known fault sequences, and command-level operational evidence. Earlier reports retain their original pins and scope. |
| AP075 and AP076–078 | Existing bounded installed-path, interruption and administrative recovery results. Reuse applicable cases without rerunning broad suites. |
| Field lab | Owns the rehearsal protocol and consolidated cross-repository evidence. Its Tier 0 and older AWS reports retain their own simulator/live status and exact revisions. |

Three fresh agent contexts each get a separate disposable run. The developer
and operator get public documentation and the reviewed archive. Supply no
private code guidance during the first attempt. Record every failed instruction,
assumption and intervention before offering a correction. A rerun must identify
its changed inputs and prior exposure.

| Role | Evidence required |
| --- | --- |
| Developer | Verify archive identity, install from package, exercise the documented Python or TypeScript consumer, submit an exact approved operation, and export evidence. Record elapsed setup and operation time, steps, interruptions and any assistance. Use the provider transcript to establish the effect count. |
| Operator | Exercise response loss, restart with retained state, a separately approved read on a known source, and revocation on the disposable connection. An unresolved original operation remains charged and is escalated without another write. Record stage, elapsed time, provider request/effect counts, and cleanup for each distinct operation. |
| Defensive reviewer | Independently choose existing documented negative and positive controls for approval, limits, replay, concurrency and role isolation. Observe native decision codes and provider-side counters. Reuse existing regression cases for the coverage matrix. |

A report distinguishes observed results from historical coverage and open gaps.
Review only redacted metrics and stable outcome codes before committing it.
Keep raw logs, private fixture state and per-run provider transcripts in the
owned temporary directories and retire them after review. Verify cleanup of
owned processes and containers. A safely unresolved effect is reported as such.

Fix demonstrated material friction in existing docs or entry points and retain
regressions for changed behavior. Preserve native authorization and recovery
semantics. Link both PRs. A passing run supports a scoped engineering rehearsal
claim. Human adoption, independent human review and production qualification
retain their existing acceptance gates.

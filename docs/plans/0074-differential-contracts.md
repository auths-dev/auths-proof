# AP074 independent differential contracts

A19 requires both mutation and acquisition/disclosure comparisons. This file
records the exact overlap and differences; neither independent reference becomes
a managed execution path. The acceptance row remains partial until all required
comparisons and exact-head hosted execution exist.

## Mutation corpus

`native_differential_tests.rs` compiles the maintained Airtable record-update and
Stripe platform-refund recipes. The Airtable fixed base/table substitution is
the same reviewed, pure expansion permitted by the independent reference. No
network request is sent to those resources. Each request case has an actually
signed native grant/action/proof, ordinary verification, and either a refusal or
an immutable bound effect. Successful cases also obtain and revalidate a real
exact-effect approval signed by public fixed test keys. There is no admission,
entry permit, credential, provider execution or human-presence claim.

The retained native corpus has 28 request cases and 22 response cases across
the two families. `qualification/reference/ap074_differential.py` calls the
unchanged `airtable_record.py`, `stripe_platform.py`, `fresh_evidence.py` and
`provider_readback.py`; the references never import the gateway implementation
or this comparator. Every case name/count is required, including duplicate and
omission refusal. A negative comparator test mutates request bytes, native
decisions, case inventory, observations, recovery targets and resource scope.

| Contract | Comparison and limits |
| --- | --- |
| Request equality | Exact method, URL, body bytes, content type, ordered noncredential headers, echo and idempotency key agree for all shared positive inputs. |
| Shared refusal | Missing/extra fields, wrong namespace/recipe, operation limits, invalid values and signed amount-ceiling violations refuse on both sides. Refusal codes are retained separately: reference input validation and native authorization occur at different stages. |
| Resource scope | The independent qualification pool refuses an otherwise well-shaped unowned resource. A native grant/recipe can authorize that resource without knowing the qualification pool. These expected differences are required assertions, not accepted unexplained drift. |
| Provider guard | Native compilation is not the separately fenced fresh provider-read decision. Independent Stripe guards separately demonstrate the exact 50 percent ceiling and currency binding; this corpus does not claim to execute the native live guard. |
| Observation | Exact expected value plus exact declared echo links the generic native observation. Wrong value/echo and unavailable JSON retain distinct facts. Duplicate members, malformed/nonfinite JSON and over-limit responses never become a definitive observation. |
| Full domain witness | Independent references additionally check the record identity or refund payment, status, currency and live-mode facts. A generic recipe that projects one value and echo does not acquire those extra domain predicates. Missing echo can be native state equality while the full independent witness refuses. |
| Refund identity | The independent Stripe reference discovers a refund by its action-bound echo. A different safe refund ID alone does not invalidate that witness. It never trusts an application-supplied refund locator. |
| Recovery capability | Airtable has a verified record locator before any write response. Stripe's native response-derived locator is unavailable without the recorded response; a declared idempotency key cannot recreate it or confer a new entry permit. The independent reference can instead find exactly one action-bound refund in its own bounded listing. That discovery is an intentionally different test-only capability, not a native recovery grant. |
| Path closure | Native response locator extraction refuses a bare dot segment. A slash inside a value stays percent-encoded within one closed segment. The reference's refund identifier grammar is narrower. |

The source-contract Python workflow first executes the native generator with
fixture updates disabled, then executes the independent comparison and retains
both artifacts. The report hashes the exact native corpus and relevant source
files. A checked-in report alone is not fresh execution evidence. Required
hosted results must identify the actual tested source/PR-merge revision and run.

## Acquisition/disclosure boundary still to implement

AP070 remains an independently implemented application-owned Python/SQLite
reference. Its admission and release behavior may be compared on a precisely
named post-authorization contract without rewriting its source or supplying it
managed credentials or entry permits. It is not yet included in the mutation
corpus above.

Comparisons must preserve these differences:

- Native acquisition response and separate recipient ACK are distinct facts.
  AP070's transactional release commitment has no authenticated recipient ACK
  protocol and cannot be relabeled as one.
- Native replay may return retained historical facts. AP070 can refuse a
  repeated challenge. The shared property is no new external entry or charge;
  equality of public result codes is not required across those contracts.
- AP070 task-lifetime content ceilings and metadata-plus-content provider byte
  reservations differ from native fixed-window response ceilings and separate
  disclosure byte allocations. Preserve raw values and named units; do not
  force unlike quantities into equal totals.
- A native durable multi-process/adapter guarantee cannot be inferred from
  AP070's application runtime lock or SQLite demonstration.

Future comparisons must execute the unchanged reference, pair it with actual
native file/PostgreSQL histories, and establish conservation, revocation before
release, crash/reopen and no automatic repeated disclosure within the overlap.
All remaining A19 requirements stay open until that evidence exists. No managed
guarantee is claimed for AP070.

# Dependency verification repair for AP076

The completed-source dependency gate reported [RUSTSEC-2026-0462](https://raw.githubusercontent.com/RustSec/advisory-db/main/crates/rmcp/RUSTSEC-2026-0462.md) against rmcp 1.8.0. The advisory describes unbounded buffering in its optional Streamable HTTP clients, repaired upstream in 3.9.0 ([upstream change](https://github.com/modelcontextprotocol/rust-sdk/commit/3e0156c1eaf1573a1b878e2a8998d2fa2d0b1439)).

The previous feature graph enabled only rmcp's server feature with defaults disabled; those HTTP clients were absent. Upgrade to the fixed release instead of adding an advisory exception. The only used upstream API is a model value, so disable the unused server feature as well. This avoids importing the server's new UUID randomness requirement into WebAssembly. No client, server or transport feature is needed by the converter. Cargo.lock updates rmcp and removes any newly unneeded resolution, retaining the other package versions. This is a direct prelaunch dependency cutover, with no legacy adapter or second protocol reader.

The sole production import is the official CallToolRequestParams adapter in auths-profile-mcp. The new release replaces the old task parameter with continuation inputs and opaque request state. Reject the presence of metadata, input_responses or request_state, including empty values. This adapter supports immediate calls and cannot authorize task/continuation execution. Keep Auths' canonical mcp/2 action and stable error code; add exact-byte regression evidence for the existing immediate call and rejection evidence for every new control field.

Construct architecture, source-closure, gateway closure, proof-coverage and semantic records atomically. Verify the failed dependency policy, the affected profile's tests and workspace compilation before publishing the collected repair. The completed-head CI remains acceptance authority. No qualification claim is granted by a dependency update.
